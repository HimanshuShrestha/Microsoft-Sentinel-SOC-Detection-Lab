# Case #002 — Discovery and Supporting Telemetry Correlation

## Case Overview

**Date:** September 23–24, 2026  
**Endpoint:** SOC-WIN11  
**User:** SOC-WIN11\socanalyst  
**Environment:** Controlled Lab  
**Severity:** Informational / Lab Investigation  
**Final Verdict:** Benign / Expected Test Activity  
**MITRE ATT&CK Tactic:** Discovery

## Objective

The purpose of this investigation was to extend the initial discovery investigation by generating additional endpoint telemetry and practicing correlation across multiple event types.

Controlled discovery, file-creation, registry, and PowerShell activity was examined to determine whether supporting events could be reliably associated with the investigated processes rather than assuming that events occurring within the same time window were related.

The investigation focused on correlating events using process identifiers, process ancestry, affected objects, command content, user context, and timestamps.

## Telemetry Investigated

| Telemetry | Investigation Focus |
|---|---|
| Sysmon Event ID 1 | Process creation and process relationships |
| Sysmon Event ID 3 | Network connections |
| Sysmon Event ID 10 | Process access |
| Sysmon Event ID 11 | File creation and the process responsible for creating the file |
| Sysmon Event ID 13 | Registry value modifications |
| PowerShell Event ID 4104 | PowerShell script-block content |

## Discovery Activity

Controlled discovery activity was generated on the `SOC-WIN11` endpoint to represent reconnaissance that could occur after access to a Windows system.

The activity included commands used to examine user identity, privileges, group membership, accounts, administrator membership, and system/network information.

The resulting process-creation telemetry provided the starting point for examining whether additional endpoint activity could be correlated with the discovery activity.

## File Creation Correlation

A controlled file-creation event was generated by creating:

`C:\Windows\Temp\SOC-EVENT11-TEST.txt`

Sysmon Event ID 11 successfully recorded the activity. The event contained the `TargetFilename`, identifying the file that was created, as well as the `ProcessGuid` associated with the process responsible for the activity.

The observed file-creation event was associated with:

`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`

Rather than correlating the file creation with discovery activity based only on timestamps, the `ProcessGuid` provided a stronger relationship between the file event and its process context.

This demonstrated that process identifiers can provide stronger correlation evidence than temporal proximity alone.

## Registry Activity Analysis

Sysmon Event ID 13 telemetry was reviewed for registry modifications occurring around the investigation window. Particular attention was given to `Run` and `RunOnce` locations because these registry paths can cause programs to execute automatically and may be abused for persistence.

A `RunOnce` modification associated with `OneDriveSetup.exe` was identified during the investigation. Rather than classifying the event as suspicious based only on the registry location, I examined the process responsible for the modification, the `TargetObject`, and the value recorded in `Details`.

The observed entry was consistent with OneDrive update/uninstall cleanup activity and did not provide evidence of malicious persistence.

Additional BAM-related registry activity associated with PowerShell was also reviewed. The presence of PowerShell-related registry activity alone was not considered sufficient evidence of malicious behavior.

This reinforced the importance of evaluating registry modifications using the responsible process, registry path, written value, and surrounding context rather than treating a security-relevant registry location as automatically malicious.

## PowerShell Script Block Logging

PowerShell Script Block Logging was enabled to provide additional visibility into PowerShell activity.

Event ID 4104 was successfully generated and validated using controlled PowerShell commands, including commands such as `Get-LocalGroupMember` and `Get-ItemProperty`.

While Sysmon Event ID 1 provides visibility into process creation, PowerShell Event ID 4104 provides visibility into PowerShell script blocks and commands executed within PowerShell. This is particularly useful for PowerShell cmdlets that may execute without creating a separate child executable.

The additional telemetry demonstrated how process-level visibility from Sysmon and command/script-level visibility from PowerShell logging can complement each other during an investigation.

## Correlation Approach

Events occurring near the same timestamp were not automatically considered related.

Correlation was based on multiple contextual fields where available, including:

- `Computer`
- `User`
- `ProcessGuid`
- `ParentProcessGuid`
- `Image`
- `ParentImage`
- `CommandLine`
- `TargetFilename`
- `TargetObject`
- Event timestamps

Process relationships were given greater investigative weight than temporal proximity alone.

For example, a file created shortly after discovery activity could be relevant, but the timestamp alone would not establish that the discovery process caused the file creation. Process identifiers and ancestry provide stronger evidence for establishing that relationship.

## Analyst Assessment

The investigation demonstrated how discovery activity can be expanded into a broader telemetry-correlation workflow rather than evaluated as an isolated set of commands.

File-creation telemetry was successfully generated and correlated with its responsible PowerShell process using Sysmon Event ID 11 and `ProcessGuid`. Registry modifications were examined using Event ID 13, including potentially security-relevant `RunOnce` activity that was ultimately consistent with legitimate OneDrive maintenance. PowerShell Event ID 4104 provided additional visibility into commands executed within PowerShell.

The activity was generated as part of a controlled lab simulation and was therefore classified as **Benign / Expected Test Activity**. Review of the surrounding telemetry did not identify malicious follow-on behavior that contradicted the known provenance of the activity.

## Key Lessons Learned

- **Time proximity does not prove correlation.** Events occurring within the same investigation window may be unrelated. Process identifiers and ancestry provide stronger evidence when establishing relationships between events.

- **Event-specific fields matter.** `TargetFilename` is important when investigating Sysmon Event ID 11, while `TargetObject` and `Details` provide important context for Event ID 13 registry activity.

- **Potentially suspicious locations require context.** Registry locations such as `Run` and `RunOnce` can be abused for persistence, but they are also used by legitimate software. The responsible process and written value must be examined before reaching a conclusion.

- **Different telemetry sources provide different visibility.** Sysmon Event ID 1 provides process-creation information, while PowerShell Event ID 4104 provides visibility into PowerShell script blocks and commands.

- **Discovery activity alone does not establish compromise.** Discovery commands can warrant investigation, but supporting telemetry and contextual evidence are required before determining whether activity is malicious.

- **Analyst conclusions should be evidence-based.** Investigation should distinguish between observations, correlations, and conclusions rather than treating every event occurring near an alert as part of the same activity.
