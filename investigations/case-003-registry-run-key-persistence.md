# Case 003 – Registry Run Key Persistence Investigation

## Case Summary

This investigation used Atomic Red Team to generate controlled adversary activity on the SOC-WIN11 endpoint. The objective was to investigate the activity using Microsoft Sentinel, Sysmon, and PowerShell telemetry rather than relying on knowledge of the Atomic test itself.

The investigation identified PowerShell modifying the current user's Windows Run key to establish a persistence mechanism. Evidence was correlated across Sysmon Event ID 1, Sysmon Event ID 13, and PowerShell Event ID 4104 using timestamps, ProcessGuid relationships, command-line data, and script-block content.

The activity was mapped to MITRE ATT&CK T1547.001 – Registry Run Keys / Startup Folder.

The persistence artifact was subsequently validated directly on the endpoint, removed using the Atomic Red Team cleanup procedure, and independently verified as removed.

---

## Environment

- Endpoint: SOC-WIN11
- SIEM: Microsoft Sentinel
- Endpoint telemetry: Sysmon
- PowerShell logging: Script Block Logging (Event ID 4104)
- Adversary simulation: Atomic Red Team
- Atomic technique: T1547.001 – Registry Run Keys / Startup Folder
- Atomic test: Test 9 – SystemBC Malware-as-a-Service Registry

---

## Investigation Approach

Rather than immediately filtering for a specific event, I began by reviewing telemetry surrounding the activity window.

The initial investigation process was:

1. Review the surrounding timeline.
2. Identify process creation and discovery activity.
3. Reconstruct process relationships using ProcessGuid and ParentProcessGuid.
4. Correlate the suspicious PowerShell process with additional Sysmon telemetry.
5. Investigate registry modifications.
6. Correlate registry activity with PowerShell Script Block Logging.
7. Determine whether the persistence mechanism subsequently executed.
8. Validate the persistence artifact directly on the endpoint.
9. Remediate the artifact.
10. Verify successful remediation.

---

## Initial Timeline Review

The controlled activity began at approximately:

`2026-10-02 17:41 UTC`

A broad review of the surrounding telemetry identified multiple event types, including:

- Sysmon Event ID 1 – Process Creation
- Sysmon Event ID 3 – Network Connection
- Sysmon Event ID 7 – Image Loaded
- Sysmon Event ID 10 – Process Access
- Sysmon Event ID 11 – File Create
- Sysmon Event ID 13 – Registry Value Set
- PowerShell Event ID 4104 – Script Block Logging

This broad review helped avoid focusing on a single telemetry source too early in the investigation.

---

## Process Investigation

Sysmon Event ID 1 showed discovery activity including `whoami.exe` spawned from PowerShell.

Process relationships were investigated using `ParentProcessGuid` and `ProcessGuid`.

A PowerShell process associated with the activity contained a command using `Set-ItemProperty` to configure the current user's Windows Run key and create a value named `socks5_powershell`.

The suspicious PowerShell process had the following ProcessGuid:

`{e9947f76-ecc3-6abf-0e03-000000002400}`

This ProcessGuid was used as a pivot to investigate additional telemetry generated by the same process.

---

## Registry Persistence Evidence

Sysmon Event ID 13 recorded a registry value modification by the same PowerShell ProcessGuid.

The relevant registry target was:

`HKU\<USER-SID>\Software\Microsoft\Windows\CurrentVersion\Run\socks5_powershell`

The registry value contained:

`powershell.exe -windowstyle hidden -ExecutionPolicy Bypass -File`

The event showed:

- EventType: SetValue
- Image: powershell.exe
- User: SOC-WIN11\socanalyst
- RuleName: T1547.001 – Registry Run Keys / Startup Folder

Because Windows Run keys can automatically execute configured programs when a user logs on, this modification represented a persistence mechanism.

---

## PowerShell Script Block Correlation

PowerShell Event ID 4104 was investigated to determine what PowerShell code had been processed around the registry modification.

The initial search produced substantial Atomic Red Team framework activity. To reduce noise, the events were grouped by script path. A large number of script blocks had no associated path, so those events were examined further.

Short script blocks were then used as a triage pivot.

This exposed PowerShell script-block content using `Set-ItemProperty` to create the `socks5_powershell` value under:

`HKCU:\Software\Microsoft\Windows\CurrentVersion\Run`

The configured value was:

`powershell.exe -windowstyle hidden -ExecutionPolicy Bypass -File`

This provided an additional telemetry source confirming the behavior observed in Sysmon Event ID 13.

---

## Evidence Correlation

The strongest evidence occurred within approximately three seconds:

| Time (UTC) | Telemetry | Observation |
|---|---|---|
| 17:41:21.240 | PowerShell 4104 | Atomic test invocation observed |
| 17:41:23.201 | Sysmon Event ID 1 | PowerShell process creation observed |
| 17:41:23.649 | PowerShell 4104 | Run-key modification script observed |
| 17:41:23.721 | Sysmon Event ID 13 | Registry Run-key value modification recorded |

The combination of process telemetry, script-block content, registry modification telemetry, and ProcessGuid correlation provided evidence that PowerShell established registry-based persistence.

---

## Supporting Telemetry Review

Additional telemetry associated with the suspicious PowerShell ProcessGuid was reviewed.

### Sysmon Event ID 7

Image-load activity was reviewed but did not provide additional evidence materially expanding the persistence activity.

### Sysmon Event ID 11

A file creation event involving PowerShell startup/profile data was identified. The available evidence was insufficient to attribute this file as a malicious payload, so it was not treated as evidence of payload creation.

### Child Process Review

Sysmon Event ID 1 was searched for processes whose ParentProcessGuid matched the suspicious PowerShell ProcessGuid.

No child process creation was observed from that ProcessGuid in the collected telemetry.

These findings were treated as supporting or negative evidence rather than being interpreted as malicious solely because they occurred near the suspicious activity.

---

## Persistence Execution Check

After confirming that the Run-key value had been created, subsequent Sysmon Event ID 1 telemetry was reviewed for PowerShell process creation matching the command stored in the registry value.

No subsequent execution of the persisted PowerShell command was observed within the investigated telemetry window.

This distinction was important:

**Persistence was established, but subsequent execution of the persisted command was not observed in the investigated telemetry.**

---

## Endpoint Validation

The persistence artifact was validated directly on SOC-WIN11 using PowerShell:

```powershell
Get-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name "socks5_powershell"
```

The endpoint returned the `socks5_powershell` value with:

`powershell.exe -windowstyle hidden -ExecutionPolicy Bypass -File`

This confirmed that the registry value identified through Sentinel telemetry remained present on the endpoint.

---

## Remediation

Because the activity was generated using Atomic Red Team, the corresponding cleanup procedure was used:

```powershell
Invoke-AtomicTest T1547.001 -TestNumber 9 -Cleanup
```

Atomic Red Team reported successful completion of the cleanup operation.

The endpoint was then independently queried again:

```powershell
Get-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name "socks5_powershell"
```

PowerShell reported that the `socks5_powershell` property did not exist at the Run-key path.

This verified that the persistence artifact had been successfully removed.

---

## MITRE ATT&CK Mapping

**Technique:** T1547.001 – Registry Run Keys / Startup Folder

**Tactic:** Persistence

The activity modified the current user's Windows Run key so that a configured PowerShell command could execute automatically during user logon.

---

## Final Disposition

**Benign – Authorized Security Testing**

The observed activity originated from a controlled Atomic Red Team simulation.

Although the activity was authorized, the investigation was performed using the same evidence-driven process that would be applied to potentially malicious activity. The investigation confirmed registry-based persistence, correlated multiple telemetry sources, evaluated supporting and negative evidence, validated the endpoint state, performed remediation, and verified successful cleanup.

## Key Takeaways

This investigation strengthened practical skills in:

- Microsoft Sentinel investigation
- KQL-based telemetry analysis
- Sysmon Event ID analysis
- PowerShell Script Block Logging
- ProcessGuid and ParentProcessGuid correlation
- Process ancestry reconstruction
- Registry persistence analysis
